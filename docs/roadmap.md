# 決まっていないことと次の候補

2026-10-29 時点。

## 決めていただくこと

- **F-Droid の署名**：3 つの経路を同じ署名にそろえる（再現可能ビルドが前提）か、F-Droid 自身の鍵で署名させるか（[distribution.md](distribution.md)）。
- **日本語版 Wikipedia を学習に使うか**：CC BY-SA の義務が学習させたモデルに及ぶかがはっきりしない（[conversion.md](conversion.md#コーパス)）。
- **鍵の運用**：アプリ署名鍵とアップロード鍵のパスワードを分ける（アップロード鍵の作り直しをすすめている）、鍵のバックアップを 2 か所以上に取る。

## 次の候補（おすすめ順）

1. ~~くだけた文の評価データを作る~~（2026-10-29 に済み。[conversion.md](conversion.md#調整に使っていない評価データevaluationsettest)）。
   使っていて気づいた誤変換を「読み → 出てほしかった表記」の形で集め、品質回帰テストに足すのは引き続き有効。
2. **F-Droid に登録する。** fdroidserver の環境でのビルドと一致の確認、メタデータ、署名の決定（[distribution.md](distribution.md#f-droid-で残っている作業)）。
3. **言語モデルのエントロピーによる刈り込み。** 4 億字分のモデルを 20MB 台に収められるかを試す。
4. **並べ替えモデルの改良。** 左の文脈を特徴に足し、強くなった言語モデルの上で効果を測り直す（[reranker-prototype.md](reranker-prototype.md)）。
5. **言語モデルの読み込みを速くする。** 起動時に全キーを走査して作っているバケットの索引をファイルに持たせれば、0.3.0 で 181ms（SCV49）の読み込みを縮められる。

## 分かっている制限

- 雑談でひらがなで書かれることの多い語（きれい、いろいろ、なかなか など）を漢字にしがち。学習で使う人ごとには直る。

- 「ひとりで」のように助詞が付いた文節では「1人で」が候補に出ない。
- 「ローマ字文を書く」は 0.3.0 のモデルでは「ローマ字分を書く」になる（ウェブの文に「◯文字分を」が多いため）。
  文脈を保つ仕組みそのものは、テストの中で小さな言語モデルを作って確かめている。
- 高さの調整中は変換候補が出ない。
- 音声入力は、端末内認識に対応した端末（Android 12 以降の一部）でしか使えない。
- コピーの直後にクリップボードがすぐ上書きされると、その画像を履歴に取りこぼすことがある。
